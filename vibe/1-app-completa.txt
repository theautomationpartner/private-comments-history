===============================================================================
QUÉ ES LA APP
===============================================================================

Las columnas de texto de monday se reemplazan en cada edición: no guardan versiones. Un board de
proyectos tiene 5 columnas de texto donde el equipo escribe seguimiento, y una automatización de
monday va guardando cada cambio como un ítem nuevo en un board privado de historial.

Esta app se abre dentro de un proyecto y muestra ese historial, separado por columna de origen.
La app NO genera el historial: solo lo lee. La automatización ya existe y ya está funcionando.

--- Conversión de fechas: usar SIEMPRE `value`, NUNCA `text` ---

Esto es crítico y está verificado contra la API de monday. En una columna de tipo date:

  value  ->  {"date":"2026-07-27","time":"08:05:08"}   <- UTC real
  text   ->  "2026-07-27 05:05"                        <- YA convertido al huso de quien consulta,
                                                          y sin ningún indicador de zona

Si se usa `text`, new Date() lo interpreta como hora local del navegador y el desfasaje se aplica
DOS VECES. En este caso concreto eran 6 horas de error, en una app cuyo sentido son las fechas.
Los campos `... on DateValue { date time }` tienen el mismo problema que `text`.

function toUtcIso(rawValue) {
  if (!rawValue) return null;
  try {
    const { date, time } = JSON.parse(rawValue) || {};
    return date ? `${date}T${time || "00:00:00"}Z` : null;
  } catch {
    return null;
  }
}

    return (link.linked_item_ids || []).map(String).includes(String(itemId));
